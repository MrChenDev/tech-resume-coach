# 大学生技术岗位地图

本文件用于启动分析，不是企业招聘标准全集。岗位要求以当次 JD 和可核实的招聘信息为准。

## 学生与应届生常见证据

没有多年全职经历并不等于简历无内容。可评估的证据包括：课程设计、个人/团队项目、实验室科研、竞赛、开源贡献、实习、社团技术工作、技术博客/作品集、相关课程与证书。对每项经历核实：做了什么、本人承担什么、用了什么方法、遇到什么限制、结果如何、能否复现或展示。

## 岗位方向及常见关注点

| 方向 | 重点核对的能力证据 | 常见项目追问 |
|---|---|---|
| 软件研发 / 后端 | 编程基础、数据结构与算法、接口与数据建模、并发/性能/可靠性、测试与协作 | 个人负责的模块、关键设计取舍、异常处理、性能瓶颈、测试方式 |
| 前端 / 客户端 | 页面/交互实现、组件与状态管理、网络/存储、性能、兼容性、工程化 | 复杂交互、状态边界、性能优化依据、错误与空态处理 |
| 嵌入式软件 | C/C++、MCU/SoC、外设与总线、RTOS/驱动、调试、资源约束 | 中断/任务设计、时序问题、内存限制、抓取和定位故障的方法 |
| 硬件 / 电子 / FPGA | 电路/数字逻辑、器件与接口、原理图/PCB/仿真、测量与调试、验证记录 | 设计指标、器件取舍、信号/时序问题、测试条件和结果 |
| 数据工程 / 大数据 | SQL、数据建模、ETL/ELT、批流处理、调度、质量与治理 | 数据量和口径、增量策略、失败重跑、数据质量检查、成本/延迟 |
| 数据科学 / 算法 | 统计与建模、特征/实验、指标、数据泄漏意识、部署或复现能力 | 基线、数据划分、指标选择、误差分析、线上/离线差异 |
| 测试 / 测开 | 测试设计、缺陷分析、自动化、接口/性能/稳定性、质量闭环 | 测试范围取舍、边界用例、缺陷复现、自动化收益和维护成本 |
| 运维 / SRE / 云平台 | Linux/网络/脚本、监控告警、部署、容器/云、故障处理、自动化 | 可用性目标、排障过程、容量判断、回滚、事后改进 |
| 安全 / 网络 / IoT | 威胁或协议分析、设备/网络调试、权限/密钥、端到端安全、可靠性 | 威胁模型、攻击面、协议/设备约束、验证方式、修复闭环 |

这些是分析视角，不表示每个校招岗位都要求全部技能。先看具体岗位职责和必需条件，再判断相关性。

## 技术能力写法

- 技能按“能独立完成的任务 + 使用场景 + 证据”表达，不仅列技术名词。
- 熟练程度以项目证据校准；不要把接触过、上过课写成精通。
- 课程与证书用于补充基础背景，不能替代项目和个人贡献证据。
- 团队项目中要区分团队结果和本人负责部分。
